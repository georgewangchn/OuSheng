## 二、五问题根因（第一性原理 + 正逆推演）

### P1 严重分叉导致故障

「分叉」本轮有两个物种，根因不同，必须分开判：

**物种一：板仓 git 分叉（§42 / §48）**
- 正向（协议理想链路）：单板单写源 → 每写必 sync 收口 → 分叉结构性不可能。
- 逆向（实跑偏差）：PM 写板有两个物理入口——pm-mac 板仓 clone（Mac CLI / 会话）与
  A 机板仓（座位写 + web 驾驶舱）。11-13 夜 pm 侧积压 40 提交未推；11-15 晨 PM 从 Mac
  推板与 A 机座位本地写交错。两次都是 **PM 双写源制造**（§48 已自我归因：「我的操作事故」）。
- 根因判定：**裁决缺口**（PM 写面唯一化从未正式拍板，§48 只是协议段纪律「首选」）+
  执行偏离（纪律有了仍双写）。
- 反事实：若 PM 只从驾驶舱（A 机板仓）写，两次分叉都不可能发生——单写源永不分叉，这不是
  概率改善，是物种灭绝。

**物种二：驱动器分叉（§37 / §47）**
- canonical cruise-loop.sh 与实栈手搓 fork 的拉锯三起三落（loop2/loop3 → §37 归一 →
  v5 → §47 座位补 sleep 被产品覆盖 → §46 并回 v5）。§47 教训已裁：**并回时 diff 双侧——
  fork 多出来的块往往是产品漏的**（该教训本身是健康的机制演化）。
- 残留缺口：**doctor 不查可选资产漂移**（cruise_cmd_test 明确断言「optional asset must
  not break doctor」）。驱动器装了但分叉了 = 无人可见。且 **A 机 v5 自 11-14 12:28 长跑，
  跨 v0.3.6 三修（fad7059 基线睡眠 / 27f3b26 分叉等待 / d4040c4 ctx 水位门）发布**——在跑
  驱动是否含修复未验证（列入 §五）。若不含，§47 连轴与 §49 膨胀在 11-15/16 夜仍在复发，
  这与「deepseek 大半费用」的量级吻合。
- 根因判定：**产品缺口 = 部署校验缺最后一公里**（机械锁修了 ≠ 在跑的二进制/脚本修了；
  事故归宿链「二进制升级 → 实栈重跑」无 doctor 可查节点）。

### P2 大量 token 空转、deepseek 费用大半烧掉

- 正向（理想链路）：三闸（时窗/轮顶/idle）+ idle 指数退避（§35 P3）+ 维持轮退避（§43 H）
  + 轮后基线睡眠（§47）+ ctx 水位门强制换代（§49）+ 模型路由 WAIT/CODE（§35 P5）。
- 逆向（实跑）：六个 token 燃烧机理全部实锤过——§37 四因（续代链断/值守分层失效/零 delta
  维持轮/重上下文）+ §46 盲区空转 + §47 flash 连轴 + §49 膨胀瘫队。**全部已在 canonical
  v0.3.6 锁死**。
- 残留两件：
  1. **部署脱节**（同 P1 物种二）：修复在产品仓，不在 A 机在跑的进程里。
  2. **预算闸缺位**：三闸以「轮次/时间」计，无「钱」计。§33 延后判据「token 计量需求实锤」
     ——deepseek 账单事故即实锤。§49 已证明 driver 可读每轮 cache.read（ctx 门在用），
     计量源已存在，预算闸是低成本收口。
- 反事实：若 v0.3.6 三修当夜在跑——§47 连轴被基线睡眠灭、§49 膨胀被水位门灭（150K 强制
  换代）、§46 盲区被恢复节修复。账单事故是**已知病 + 已有药 + 药没喂到嘴里**。

### P3 web（A 机）与 OuSheng 双处操作，环境问题，PM 不知该在哪操作

三面并存（现状盘点）：

| 面 | 载体 | 身份 | 能做什么 | 问题 |
|---|---|---|---|---|
| ousheng web 驾驶舱 | A 机 :18000（**loopback 硬绑**） | 板仓 me=pm | 发单/派活/状态/ack/拍板/presence/全局观测 | 手机难直达（§24 双封口裁决：「远程访问需另行裁决带鉴权方案」——欠账未裁） |
| opencode web 会话 | A 机 serve | 会话座位 agent | PM 与 agent 对话、纠偏 | 在此指挥写板/拍板 → 执行身份是 agent ≠ pm → 写路径拒（§23）→ PM 感受为「环境问题」 |
| pm-mac CLI | Mac 板仓 clone | me=pm | 全量 CLI | **写板 = 双写源 = P1 物种一直接根因** |

- 逆向推演「环境问题」感受来源：①Mac 写板制造分叉 → 全队被分叉门停 → 「环境坏了」；
  ②opencode 会话里让 agent 拍板被拒（身份门正确地拒绝）→ 「OuSheng 也登陆操作，出问题」；
  ③三面无判决 → PM 每次操作都要重新猜哪面合适。
- 根因判定：**裁决缺口**——三面各有合法性但无分工判决；§24 自己留的「远程访问另行裁决」
  欠账两年式悬空（loopback 安全裁决 vs 手机实用需求互相顶牛，没人拍板就一直顶）。
- pm 提议方向（统一到 pm web 窗口）判定：**与既有裁决完全同向**——§48「首选统一经座位机
  操作（单写源永不分叉）」+ §34 A 模式坍缩「板成唯一界面，agent 窗口退为例外通道」。
  提议成立，缺的是把「首选」升格为「唯一」并补齐驾驶舱缺口（见 R1/R2/R5）。

### P4 大量任务没实现、进展缓慢

慢不是单一根因，是四夜损失的求和（§一表格）+ 两个结构性残留：

1. **PM 消费仪式缺位**：夜里 human 门项（拍板/C2/Q:）全部正确挂起攒批，但 PM 晨间没有
   固定仪式清挂起 → 白天 agent 领新活再挂 → 夜里再挂——挂起清单滚雪球，等效吞吐骤降。
   机制面（Q: 攒批 + 自动清理 + 驾驶舱挂起操作面）全有，缺的是**流程**：晨检不是习惯。
2. **PM 手动巡航与 runner 抢资源**（§43 E 残留判据原文：「pm 手跑再引资源事故→做统一
   入口」）——本轮四夜实锤触发。pm 会话手动巡航不受信号量、不受 flock、不进三闸，是
   资源面与审计面的双重法外之地。

- 反事实：四夜损失里，机械可防的（§46/§47/§49 + 双写源）全部已有锁或提案；剩余两残留
  （晨检仪式、统一入口）分别收口于 R6 与 R2。没有「agent 干不了活」的证据——每次瘫队
  都是管道问题不是能力问题。

### P5 启动双入口（脚本可启、pm 侧可启），要唯一入口

- 现状盘点（§45 后）：①A 机 shell 脚本 / `systemctl start ousheng-cruise@<座位>`（标准
  两形态，都是人启动 ✓）；②pm 会话手动巡航（法外之地，P4-2）；③内网三台 timer 仍
  enabled（§45 待办未清偿，网络恢复第一件事 disable+mask）。
- 根因判定：**裁决缺口 + 判据已触发**。§45 把「开窗闸」收给人了，但没裁「人从哪个门进」。
  门有三个，事故（§42 三源并发）已把 §43 E 判据打实。
- 提案：见 R2。pm 倾向「pm 的 web 窗口」= 驾驶舱点火——与 R1（PM 唯一面）同构成立：
  启动=人（§45）不变，按钮是人在点；单写源（写路径走 A 机）不变；canonical 前置校验
  fail-closed（分叉驱动拒绝点火）把 §37「驱动器=协议资产」从纪律升为门。

## 四、裁决提案（待 pm 拍板 → 入档案 §50）

### R1 PM 操作面唯一化：驾驶舱 = 唯一写面

- **判决**：PM 全部板写操作收敛 **ousheng web 驾驶舱**（A 机）；**opencode web 会话 =
  对话例外通道**（对某座位 agent 的交互纠偏，不承载板写与拍板——拍板回驾驶舱，§23 结构
  上也不可能在会话里借 pm 身份）；**pm-mac CLI = 只读观测**（status/report/list/show/
  team list）；**pm 当执行位手动巡航 = 死法**（§42 公共放大器实证；PM 是方向盘不是轮子）。
- 正向推演：单写源机械成立（驾驶舱写路径全走 A 机板仓）→ P1 物种一灭绝；PM 操作不再有
  「猜哪面」成本；审计面归一（全部 PM 动作在驾驶舱 activity）。
- 反事实：驾驶舱不可达（A 机宕）时 PM 写板？——SSH A 机 shell 走同一板仓，单写源不破；
  Mac clone 只读不写，分叉不可能。紧急拍板无网？——拍板本就是 human 门，等网不是缺陷。
- 边界诚实：Mac clone 保留（只读观测合法）；admin 类低频操作（migrate/board 归一/
  resolve-owner）仍在 A 机 shell——驾驶舱不扩配置面（§24 红线不动）。
- 机械锁：无新锁（结构性收口，现有 §24 锁已盖）；协议段 pm 纪律行更新。

### R2 点火唯一入口：`cruise ignite`（CLI + 驾驶舱按钮）

- **判据触发声明**：§43 E「pm 手跑再引资源事故 → 做统一入口」——11-13/11-14 两夜三源
  并发实证，触发。
- **语义**：`ousheng cruise ignite --seat <actor> [--all] [--stop]`：
  1. 座位归属校验：registry.machine == 本机（§40 machine 登记），非本机座位拒绝（点火是
     本机执行位操作，跨机点火不做——多机 = 每机一个入口，天然分布式，同 dispatch 判例）；
  2. **canonical 前置校验（fail-closed）**：座位仓 scripts/cruise-loop.sh 与内嵌
     CruiseLoopSh 逐字节比对，不一致 → 拒 + `→ adapter install --cruise` 指引（分叉驱动
     不许点火——§37 从纪律升为门）；
  3. 启动：systemd 单元存在 → `systemctl start ousheng-cruise@<seat>`（日志进 journal，
     自愈在岗）；否则 nohup canonical 脚本（横幅进日志，任何启动形态可验 §37）；
  4. 幂等：座位 flock 已在驱动内（§46 BUG-179 根治），二次点火被 flock 拒 = 大声提示
     「已在跑」；`--stop` = systemctl stop / 进程组终止（§43 运维弹药：甄别活跃 MCP 子进程）。
- **驾驶舱**：/cruise 每座位行加 启动/停止 按钮（POST /cruise/ignite → handler 直调 run()
  派发器——一语义一实现，§24 结构不动；点火不是板写不是配置，是 §45 的人门被手指按下）。
- 正向推演：一个入口（驾驶舱）× fail-closed 前置校验 × flock 幂等 × journal 审计——
  三源并发结构性灭绝；PM 手机点火成为可能（与 R5 联动）。
- 反事实：绕过入口直接 `systemctl start` / ssh 跑脚本？——运维后备合法（分层诚实：root
  永远可以为王），但 doctor 漂移检查（R3）+ 协议段把绕行面压到运维事故级；恶意页面 CSRF
  点火？——Origin 门 + loopback 双封口保留，同 §24。
- 机械锁：`TestCruiseIgniteCmd`（归属拒/分叉拒+指引/systemd 调用构造/无单元 fallback）+
  `TestWebCruiseIgnite`（web=CLI 等价、非本机座位拒、GET 不点火）。

### R3 部署校验收口：doctor 增驱动器漂移检查

- **判决**：doctor 检查面扩一项——若座位仓存在 scripts/cruise-loop.sh（装过 --cruise），
  与内嵌 canonical 逐字节比对；分叉 = **FAIL** + `→ adapter install --cruise` 修复指引；
  未装 = 不查（可选资产语义不变）。「事故归宿链：机械锁 → **doctor 可查** → 二进制升级 →
  实栈重跑」——本环当前断裂，补上。
- 反事实：实栈故意跑 fork 做实验？——FAIL 可暂时忽略（退出码 1 提示实验自觉），但**可见**

## 六、一句话总结

四夜事故没有一件是巡航机制本体错了——**门从未被绕过、挂起从未失效、每次瘫队都是管道
（双写源 / 部署脱节 / 入口冗余 / 消费仪式缺位）而非能力**。产品侧 v0.3.6 已把六个 token
燃烧机理和三个瘫队机理全部锁死；本轮复盘的增量 = 四个结构性收口：**PM 一个面（驾驶舱）、
点火一个门（cruise ignite + fail-closed 前置校验）、部署一道锁（doctor 漂移检查）、
晨检一个仪式**——全部指向同一个第一性原则：绳治理方向，PM 握方向盘，牛只从一个门进。
