## 2. 发布条件（2026-09-18 推演全文）

### 2.1 三条件推导

一个发布出去的任务要成立，必须**可寻址**（落在某个系统）、**可问责**（有主，或显式标记待认领）、**可判定**（信息够执行者开工、够验收者判定）。缺一即不可执行——现状的反面不是"所有人都会执行"，而是"**没人执行**"：无主单不进任何人的 `context me`，静默孤儿。

### 2.2 状态即门槛（信息门槛挂状态，不挂创建）

反事实：信息门挂创建 → 建单摩擦 → 逼出"待定"式造假（description 填垃圾过门）。故 `backlog` 不查（先记账），`ready` 起查按类型最小信息集，`done` 必有证据（C1）。

### 2.3 active 无主硬门的统一（2026-09-18 定位推演）

- 三态定义皆为"有人正在推进"：doing 有人在干、testing 有人在验、blocked 有人会回来解阻。无主 = 语义矛盾，且没有任何执行者的 context me 会收到它。
- 合法场景（换人验证、换人接手）走 `work assign` **换主**，从不需要清空主 → 无为 testing/blocked 开特例的理由。
- 反事实：开特例 → 多分支多解释，还给"清空主逃避问责"留缝。
- 硬门定位：跨主体伤害（无人收到 ≠ 无害，是协作假象），与 C1/C2 同族；写路径硬门 + converge BLOCKER 双层。

### 2.4 分层强制

硬门只挡"进行中无主"；其余走曝光——converge：active 无主 = BLOCKER、backlog/ready 无主 = warning「待认领」、ready+ 缺信息 = warning。「信息够不够」有判断成分，硬门会逼出造假（同 2.2 反事实）。

### 2.5 四路判决（无主/信息不全信号）

不进 `context me`（注入面最小化——执行者不需要知道不归他的单）；进 `work list` + converge。`view system` 只列 active，不是无主信号面（写路径已杜绝 migrate 之外的无主 active）。

### 2.6 migrate 与无主 active

v1 `live` 卡迁移为 `doing`；owner 解析失败标 `migration_status: needs_resolution` 且无主 → converge BLOCKED（有意：无主 active 不可执行）。仅 `live` 卡——`proposed`/`agreed` 落 ready/backlog，无主仅 warning「待认领」。指定解阻路径 `migrate resolve-owner` 与 Service.Update 同门（active 且无 assignee 拒绝；role-only 解析会留下无主 active，必拒）。

### 2.7 修复记录

- `3b3a76a`：文档改真（`view system` 假承诺删除）+ `--unassigned` 隐含 open + active 门从 doing 扩三态。
- `5acd684`：二次 review——resolve-owner 补 active 门（role-only 绕道洞）+ `TestMigratedNeedsResolutionBlocks` 换真链锁（converge 不读 MigrationStatus，手构 item 与 doing 用例等价，锁不住链路）。
- **教训（入 §6 教训集）**：同语义门必须覆盖全部写径——扩门时只查了 Service.Update，漏了 migrate 直写。

## 4. 两段式配置 join（2026-09-15 三轮推演）

### 4.1 死法机理（永久出局）

- **join 审批门**：无效门——有 push 权者拦不住（他能直接 push），无权者本来进不来（没 push 权注册了也没用）；federation 退回中心规划。
- **注册表自动清理**：破坏性动作须 human。
- **responsible-human 活跃度检查**：语义，机器测不了。
- **Web 配置中心/注册服务**：零基础设施违例。
- **repos.yaml 集中上绳**：本机路径非共识，状态/共识两分判出局。

### 4.2 时间轴接力

join 管初始注册（事实）→ design 管拓扑演化（共识，动土先起 design）→ work 管执行（状态），三段无缺口。

## 8. 越位事故与身份裂缝裁决（2026-09-20，TASK-007）

**事故**：226（human 型 actor，PM）的 AI 会话自建单 TASK-007 → 自侦察生产集群 5m46s（kubectl/helm/registry）→ 自挂证据 → 自改派。绳上全程合法。靠 human 扫视才发现。

**根因三层**：
1. **身份层裂缝（最深）**：绳的信任模型是"actor 类型 = 键盘后是谁"。多机部署下，human 型 actor 的机器上跑 AI 会话 = AI 披 human 皮，所有类型门（C2 ack / design decide / F4 授予）对其失明；activity 审计无法分辨人还是 AI（问责链作废）。
2. **语义层边界（设计使然）**："侦察算执行"是语义分工判断，绳的卡点不变式明写不卡语义。越位被拦靠 human 扫视——这是设计闭环，不是绳失灵；**失灵的是"越位后绳上无痕迹"**（= 层 1）。
3. **结构层放大器**：中枢机 AI 手握生产权限 + 单子自建 + human 身份零卡点；且 assignments 的 executor 图在事故前无任何消费者（纯装饰）。

**裁决**：
- **human 挂 active 执行单 assignee = warning「决策位坐执行位」，不设硬门**——单人项目 human 亲自干活是合法常态，硬门会误伤；多机 PM 场景靠曝光让人扫视有信号（分层强制镜像：硬门挡"无主"，曝光挡"错位"）。
- **active 单 assignee 在该 system 无 executor assignment = warning「跨域执行」**——仅当该 system 已有 executor 图（存在行）才查，空图 = 未排班不查（避免早期项目噪音）。executor 图自此有第一个消费方。
- **PM 机 AI 会话必须用独立 agent 型 actor**（responsible-human = 该 human，F4 门通过），human 型 me 只留给终端亲操；`adapter install --actor` 落 AI 身份进 ousheng.json。此为车队纪律非产品门（同机多窗口协议 join 已有，无需新代码）。

**反事实**：若把两条警告升级为 BLOCKER——单人项目（human 唯一执行者）永远 BLOCKED，converge 信号失去分辨力，重蹈"waiting 算 BLOCKED"覆辙；若不修身份层只修曝光——下次事故形态变为"agent 型越权执行但账面干净"，曝光照旧抓不到，故车队身份纪律与产品曝光缺一不可。

**锁**：`TestHumanAssigneeActiveWarns` / `TestCrossDomainExecutorWarns` / `TestAdapterInstallActorOverride`。

### §8.1 本体覆盖矩阵（2026-09-20 系统性推演）

本体四层——词汇（严格解码）/ 类型（actor.type、responsibility）/ 门（写路径）/ 审计（converge 派生谓词）——**无第五层推理机**：没有任何组件从本体推出"这个动作违职责"，converge 是批量事后审计不是动作时推理。

四公理：A1 绳只能治理流经它的写；A2 卡状态合法性不卡语义（职责=语义）；A3 actor.type 语义 = 键盘后是谁（部署假设，非验证事实——绳不验也不能验）；A4 system 是逻辑域非物理机。

职责覆盖三档：
- **写路径硬门档（真 100%）**：C1/C2/F4/active 门/状态机/问责 human 型/assignee 存在性——只覆盖"跨主体伤害与状态合法性"
- **事后曝光档**：决策位坐执行位 / 跨域执行（ee6b8e9 起）
- **0% 档（原理不可修到 100%）**：绳外动作（A1）与语义分工判断（A2）——靠人扫视，这是牵引绳的本体论决定不是 bug

职责遵循的物理上限 = 流经绳的写 100% 卡死 + 流经绳的痕迹 100% 曝光 + 身份真实（车队纪律）。

## 9. 设计撤回终态裁决（2026-09-20，atw-approval-notify 事故）

**事故**：PM 取消 MQ 推送需求要撤回 draft 设计，发现** draft 无终态**——supersede 只收 agreed（draft 无权威可转移），唯一出路是手改 frontmatter 贴「已撤回」横幅 + 手切 related_items 消超前曝光警告，被迫绕绳两次（d05ea98/571d573）。无合法路径的绕过比有门的绕过更糟：它把「手改 frontmatter」常态化。

**裁决**：
- 补第四态 **withdrawn**（撤回终态）：`design withdraw <topic> --actor <owner-or-human>`。
- **这不是拍板门**（与 decide/supersede 的 human 门区分）：draft 从未获得权威、无共识可转移，收回自己的提案不构成跨主体影响——owner 即可操作（agent 可撤自己的）；非 owner 的 agent 撤别人的 draft = 跨主体伤害，拒（镜像 F4 哲学）；human 手不卡。
- 字段铁律：withdrawn 须 `withdrawn_by`、禁 `superseded_by`（无权威可转移）与 `decided_by`（从未拍板）。
- 联动零改动即生效：pending_reviews 与 converge 超前曝光都只认 `draft`，withdrawn 结构性出局——226 当日手切 related_items 的动作从此不需要，死方案持活链接属档案事实不是噪音。

**反事实**：若允许 agreed→withdrawn——已获共识的方案被 owner 单方面静默收回，下游按共识开工的工作失去权威依据且无继任者指认，重蹈「知识断链」；故 agreed 的关闭必须走 supersede（human 门 + 继任者存在）。若 withdraw 也设 human 门——agent 发起的 draft（PM 发单流程 design 先行，agent 可起草）被废弃时同样无路可走，回到手改横幅。

**锁**：`TestDesignWithdraw` / `TestDesignWithdrawnValidation` / `TestWithdrawnDesignNoAheadWarning`。

## 10. sync 收尾推送与协议段命令速查（2026-09-20，BUG-001 上绳事故）

**事故**：226 的 ui 会话发现 mlake 问题（Flink REST NodePort 31083 间歇超时），发单全程证明绳在工作——plugin 正常 sync、MCP `query_work_items`/`report_bug` 调通、BUG-001 连证据一起落地（detected_by: ui）。但用户观感是「没上绳，ousheng 没任何反应」。解剖出两个真缺口：

2. **收尾不推送**：`ousheng sync` 只 pull 不 push，plugin 时机③只跑 converge。BUG-001 自动提交后烂在 226 本地（ahead 2），全舰队不可见直至人工推送。多机车队里未推送的工单 = 不存在的工单。

**裁决**：
- `sync` 在 pull 成功后 **push 收口**（先拉齐再推，分叉态不推）；软失败——push 失败仅提示不阻塞索引与上下文，无未推提交静默。推送不进写路径（写路径 push 会在冲突时阻塞合法写入，违反「卡 agent 的写不卡 human 的手」的镜像边界）。

- 时机③ 文案补 `sync` 推送收口；plugin 不动（session.idle 每次响应后都触发，sync 含网络操作挂上去就是每 loop 轮询，违反三时机铁律；时机① 的 sync 已保证下一会话启动时兜底推送）。

**反事实**：若 push 进写路径——两机并发写后先后 push，后推者被拒，写路径报错但 YAML 已落盘，用户面对「单建了但命令失败」的中间态；sync 收口把推送的冲突面收敛到 pull 之后，失败可重试无副作用。若命令速查放进 plugin 注入——每 session token 开销，且 AGENTS.md 本就是 opencode 的 rules 载体，零额外成本。

**锁**：`TestCLISyncPushesLocalCommits`（事故形态复现：写路径自动提交 → sync → 远端必须收到）。

## 11. 工作区全局放行裁决（2026-09-20，external_directory 权限询问事故）

**事故**：224/225 每次 opencode 启动都弹 `/data/kanban`（工作区）访问权限询问。根因三层：opencode `external_directory` 默认 `ask`；TUI 的 "always" 放行**只活当前会话**（不落盘）；工作区在代码仓之外必然触发外目录门。

**裁决**：`adapter install` 第六步——把 `permission.external_directory[<workspace>/**]="allow"` 合并进**全局配置** `~/.config/opencode/opencode.json`。要点：
- **落点只能是全局**：工作区路径是机器本地信息，五件套全是入库机器中立资产放不下路径；项目配置层（根/`.opencode/` opencode.json）入库会跨机冲突。
- **合并只增不删**：key=工作区路径模式（自标识），既有键全保留；首次改动前备份 `.bak-ousheng`；`permission`/`external_directory` 非对象结构或 JSON 解析失败（JSONC 等）→ 拒绝改写、给人话指引——**不碰用户配置**；软失败不阻塞 install（权限询问是摩擦不是阻断）。

**反事实**：若把路径塞进项目 opencode.json——224 是 `/data/tide/kanban`、225 是 `/data/kanban`、本机是 `/Users/...`，同一仓克隆到别机即冲突，重蹈「协议外置分发 = 漂移死法」；若不修——每个会话人工放行一次，零摩擦上绳的承诺破产，用户迟早习惯性点掉所有权限弹窗（安全训练负向）。

**实证**：`opencode debug config` 确认 `.opencode/opencode.json` 确实被加载（文档 precedence 清单未列，1.18.31 实测有效）——五件套 MCP 配置不白写；权限解析为空印证默认 ask。

**锁**：`TestAdapterInstallGrantsWorkspacePermission`（预置 provider 合并保留 + 幂等 + 非对象结构软失败）。既有六个 install 测试补 `t.Setenv("HOME")` 隔离——install 现在写全局配置，不隔离会污染真实机。

**反事实**：若 doctor 顺带修复——修复逻辑两份（install + doctor）必然漂移，且静默改用户全局配置违背 §11；若只报不给修复命令——用户还得翻文档，等于把标准从人肉背改成翻手册查。

**锁**：`TestDoctorHealthySeat` / `TestDoctorDetectsDrift`（插件漂移/幽灵 actor/放行缺失/repo 映射失效四类）/ `TestDoctorMachineOnly`。

## 14. 双写入口语义漂移与审计空洞裁决（2026-09-21，实栈审计）

**事故**（实栈逆向推演取证）：
1. `unknown.jsonl` 4 条 `evidence_added` 且 `actor:""`（旧仓同病 = 长期存在）。根因链：`cmd/mcp` 六个写工具把 actor 当 `omitempty` 可选输入、空值直接透传 service → `gityaml.activityPath` 对空/非法 actor 静默归入 unknown 桶。**CLI 的 `evidence add` 有守卫、MCP 没有——同一写语义两套实现。**
2. MCP `add_evidence` 的 git_commit 验证用**工作区仓**（`in.Path`），CLI 用 `repos.yaml` 映射的**系统代码仓**——同源漂移，证据可能在错的仓里"验证"。

**裁决**：
- **一语义一实现**：机器本地配置（repos.yaml / me / 座位身份）与身份解析收进 `internal/machine`，CLI 与 MCP 共用同一实现（CLI 侧保留薄委托以不动调用面）。
- **身份解析链**（两个入口同一条）：显式 `--actor`/`actor` > 座位配置 `.opencode/ousheng.json`（AI 窗口身份，plugin 同读此文件）> 工作区 `.ousheng/me` > **拒绝**。座位优先于 me：me 可能是 human（PM 机终端身份），AI 的写不得默认归到人名下。
- **写路径身份硬门**（`workspace.requireActor`）：六个写方法（Create/Update/ReportProgress/AddEvidence/Ack + Assign 委托）入口一律校验——空 actor 拒（fail-closed，不许静默落 unknown 桶）；注册表非空时 acting actor 须已注册。activity 是审计线索，不可归属的写等于审计空洞。
- **git_commit 证据定位**：两入口统一走 `machine.RepoDirForSystem`（映射 > 工作区自身 monorepo 回退）。

**反事实**：若只在 MCP 层加解析——另一条未来入口（Web/其他宿主）复发；若只在 service 层加校验——AI 的调用会以难懂的错误失败（体验差、易被绕过地"随手补 actor"），且 git_commit 定位漂移依旧。两层各自解决不同问题：入口层解决"能正确归属"，service 层解决"绝不允许不可归属"。

**锁**：`TestWriteRequiresActor`（空/未注册/已注册三态 + evidence/progress 路径）、`TestMCPRejectsUnresolvedActor`、`TestMCPResolvesActorFromWorkspaceMe`、`TestMCPResolvesActorFromSeatConfig`、`TestResolveActorPriority`、`TestRepoDirForSystem`。

## 17. 验证分层裁决：不为已锁机制再造脚本（2026-09-21）

## 21. 自动收口上绳与上绳边界（2026-09-21，实栈两条反馈）

**反馈一：经常不上绳**（本地有 commit 未推）。实锤两起：BUG-015 烂在本机、BUG-002 早先烂在 226——收口之前依赖"AI 记得跑收尾 sync"（纪律依赖）。

**裁决**：
- plugin 空闲时**自动收口**：本地 `rev-list @{u}...HEAD` 检查（零网络）→ **有未推/落后才动网**（pull+push）。不做无条件每 idle sync——idle 每次响应都触发，会退化成每响应一次网络往返。
- **不确定 = 交互确认**：分叉/推送失败 → error 级大声报错 + 指引（人处理，不自动 rebase，§16）。
- 会话启动的 sync（时机①）保持。

**反馈二：自域 bug 不必上绳**。data 执行任务时发现并顺手修好自己域内的 bug——此时上绳 = 无接收方的仪式（自建、自派、自证、自关）。

**裁决（上绳边界）**：
- 上绳服务于**跨主体协作**（与卡点不变式同源：卡跨主体伤害与状态合法性，不卡语义与质量）。
- **自域**（同系统、自己顺手修、不触对外接口）→ 记入当前任务证据/进度（`evidence add <当前单>`），**不另开单**。
- **跨系统 / 跨 agent / 需人拍板 / 触及对外契约** → **必须上绳**（C2 门不豁免——契约是跨主体接口，"自域"不成立）。

**残余风险（如实记录）**：自域修复不落独立单 → PM 视野降低（缓解：仍记当前单证据 + 代码提交可查）。**判据**：若某笔自域修复事后被证明需要协作且已丢失 → 收紧本规则。

**锁**：`TestPluginReadsMachineConfigAndFailsLoud`（自动同步 + 分叉报错内容）；plugin 真编译锁（`TestPluginCompiles`）。

## 24. PM web 面板：第 4 入口 = cmd 函数直调 + 传输层双封口（2026-10-04，PM 观测带宽需求）

**需求还原**（第一性原理）：「web 页面」是方案不是需求。本质 = PM（决策层）观测带宽不足（拍板者是控制回路的传感器+执行器，CLI 终端语义是工程师语义非决策者语义）+ 执行摩擦高。控制论定位：强化人端 I/O，非替牛使劲——CLI 是徒手握绳，web 是同一根绳加手柄。

**正向推演产物（架构三决）**：
① **字面级一语义一实现**：cmd 函数是纯函数（args→streams→exit code），web handler 直调 `run()` 派发器——零抽取、零语义复制，门（类型/本地性/C2/CAS）在 cmd 函数体内结构上绕不过。对照测试锁状态等价而非代码形状。
② **身份绑定 me，表单无 actor 字段**：web 身份 = `readWorkspaceActor`（me 文件），不吸收座位配置（防 actingActor 解析出 agent），客户端永远不可指定身份——跨机借用与身份注入在 web 面**不可表达**（比 CLI 更强：CLI 允许显式 --actor，web 面连表达入口都没有）。agent 机跑 web → actor=me=agent → 拍板操作类型门自动拒 = web 天然只读拍板面。
③ **传输层双封口**：loopback 硬校验（--addr 非 127.0.0.1/[::1]/localhost 拒，fail-closed）+ Origin 门（POST 无 Origin=本地信任根放行；他源 Origin 403——浏览器侧 CSRF 借用拍板权必拒）。§23 的信任假设（本机进程=本机 human）不被网络监听器打破。

**逆向推演确认**：R1 原担心的 handler 直调 svc 绕过 cmd 门——直调 run() 后结构不可能；R2 ack 走 --file：POST 时服务端现取 current yaml + expect=current（PM ack 的是当下状态非陈旧快照）；R3 页面加载即 sync + 写后 sync 收口，观测新鲜度=中央 HEAD，失败显式 WARN 非静默；R4 表单带 expect → CAS 冲突大声失败；R5 create 限 task(todo)+bug——feature/requirement 需 design 先行（发布条件），快速表单不得绕过「动土先起 design」纪律。

**边界（七条 + 三决）**：投影+薄写适配，永不写 YAML；永不碰注册表/配置（死法边界：出现 system add/team add 按钮 = Web 配置中心复辟，红牌出局）；无前端构建链（stdlib net/http + html/template，零新依赖）；无智能无自动化无建议（哑管道，只呈现+转发明确的人动作）；读 = memory per-request（sqlite 激活判据不变）；前台命令 `ousheng web` 非常驻服务；推送通知延后（判据：真实漏看板事故）。

**锁**：`TestWebOpsMatchCLI`（五操作状态等价：status/assign/create/decide/ack，时间字段归零后 DeepEqual）/ `TestWebDecideOnAgentMachineRejected` / `TestWebAckOnAgentMachineRejected`（web 面 §23 语义保持）/ `TestWebRejectsForeignOrigin` / `TestWebLoopbackOnly` / `TestWebCmdRequiresMe` / `TestWebNoActorFromClient`（表单 actor 字段被忽略，activity 归因 = me）。

**追记（2026-10-08 PM 实用反馈：「建议区域」边界精确化）**：「无智能无自动化无建议」收窄为「**无语义性建议**」（不排序"重要性"、不判断"该做什么"——那是替人决策，绳子不干）；**规则性关注聚合合法**（blocked 时长 / active 无主 / 超期 / 依赖被砍 / 待拍板——全是协议已知事实的确定性推导，= 传感器带宽而非判断）。落地为「你的下一步」面板：固定协议严重度排序（拍板 > 卡住 > 无主 > 超期 > 依赖被砍），每行 = 事实 + 可用杠杆，无重要性话术。卡住时长从 activity 审计流推导（status_changed→blocked 最新时戳），不新增字段。

## 25. 跨系统交接信号：反向依赖 + blocked 地址化（2026-10-16，单人多系统切换信息断流）

**事故形态**（实栈反馈）：单人开发多系统，A 系统的活需要 B 系统配合或 PM 拍板。dev 切到 B 座位执行时 `context me` 看不到"A 在等我"；切到 PM 座位看不到"哪些活卡在等我出手"。绳上信息断流 = 牵引绳失去牵引职能。

**根因**：v1 卡协议 `board-protocol.md:52-53` 明文要求"依赖你的卡（反向查）"——v0.3 WorkItem 层丢了。`BlockersOf(id)` 只算正向（"我被谁阻塞"），无反向查询；`context me` 的 WorkBrief 无"被等待"标记；`work show` 无反向依赖；blocked 项不带"等谁"。

**裁决（三机制改动）**：
① **反向依赖查询**：Index 加 `DependedBy(id)`（open 项发出的反向边，已关闭项不计入）；memory Rebuild 建反向索引，sqlite 查 `work_deps WHERE dep_id=?`。S5 等价。
② **方向信号注入**：`WorkBrief` 加 `BlockedOn`（BlockersOf 派生的 DepID 列表）+ `WaitedOnBy`（DependedBy 派生）——只在注入面（`context me`/`ActorView`/`SystemView`）填充，`workBrief` 单点保持最小构造；`WorkItemDetail` 加 `DependedBy []WorkBrief`（work show detail 层）。
③ **blocked 无依赖 warning**：converge 对 blocked + 空 `depends_on` → warning `blocked without dependency (waiting on what?)`（信息缺口暴露，不额外阻塞——blocked 本身已在 blockers）。

**四路判决**：`BlockedOn`/`WaitedOnBy` 进 `context me` + `work show`（detail 层），`work list`/`view kanban` 出局（扫视层不放深链接，与 design 信号同判决）。

**卡点不变式**：反向依赖 = 方向信号（"有人在等"），不替 B 决定优先级 → 牵引绳职能 ✓；不新增存储字段（纯派生）；不新增 blocked_reason 自由文本（注入面铁律）；不新增 PM 审批队列（死法记录：审批中心永久出局）。blocked + 空 depends_on = "等非 work item"（含 PM 拍板），绳不追问语义——PM 看 description/title 自己判断。

**反事实复查**：①反向信号害 B 乱序？不成立——信号是事实，优先级判断仍在 B，单人项目只防遗忘。②计算成本高？不成立——Rebuild 时 O(n) 建反向索引。③信息过载？不成立——DAG 有界 + omitempty + 注入面只指针。

**设计**：`docs/archive/OuSheng_跨系统交接信号_design.md`。**锁**：`TestMemoryIndexDependedBy` / `TestMemoryIndexDependedByExcludesClosed` / `TestDependedByEquivalence`（S5）/ `TestContextDirectionSignals` / `TestWorkShowDependedBy` / `TestBlockedWithoutDependencyWarns`。

## 27. 上绳边界与跨系统协商（2026-10-20，PM 身影处处可见）

**事故形态**（用户实栈反馈）：交互中频繁出现"某系统说需要 PM 决策/拍板"。实栈数据：5 个 agent 的 `responsible_human` 全 = pm；49/90 单 `accountable_human` = pm；open 8 单中 3 单提"需 pm 决策/调查"。PM 成为事实上的逐事审批人 —— 与 OuSheng「牵引绳，不是牛」的初衷背离。

**个案核实**（3 单性质区分）：
- BUG-037（34 CDC 生产作业被取消）：需 sudo 权限 + 跨系统调查。权限→human 确认合理；调查→应 mlake↔data 直接协作。
- BUG-040（data 需 mlake 加 jar，触 Flink 重启）：C2 生产破坏，需 human 拍板 —— 合理。
- T-036（`cdc_reserved` 40(mlake) vs 36(data)）：**跨系统契约冲突，本应 mlake↔data 协商，却直接升级 PM** —— 典型误升级。

**根因三层**：
1. **规则不在注入面**：「自域不上绳」规则在档案 §21（按需读），**AGENTS.md 注入面没有** —— agent 每 session 读 AGENTS.md 看不到，行为失守。档案层只该放理由，行为铁律必须进注入面。
2. **缺跨系统协商默认流程**：agent 遇矛盾直接找 PM，跳过对方系统（T-036 即此）。
3. **`accountable_human` 语义未澄清**：= 最终问责（F4 防 AI 无人负责），被 agent 误读为逐事审批人。

**第一性原理依据**（基石原文）：
- §「局部复杂，全局简单」：**局部（节点内部）**保留完整代码/Memory/推理/失败尝试；**全局（看板/跨节点）**只承载 Task/Contract/Status/Owner/Dependency/Version/Event。
- §133：本地环在 plant 内部已自闭合，**边界采样只负责环与环之间的耦合，不介入环内**。
- → 「系统内部不上绳」是基石的原始设计；v0.3 实践（所有事建 work item）偏离了。基石全文未提 PM —— 绳是 agent-human 协作，不是 PM 驱动。

**裁决（三级模型 + 通知类型）**：
1. **环内（系统内部）**：不上绳、不建单、不找 PM。agent + responsible_human 直接确认（opencode 权限/对话）。自域修复记当前跨系统单证据（§21 保留）；无跨系统单则不建单。
2. **环间（跨系统通知）**：内部改动影响其他系统 → 上绳。新增 `model.TypeNotice`（`notice`）：**创建即 done**（无执行阶段——backlog 起步是为执行单元设的，通知是「已发生变更事实的广播」）；最小信息集 = description（变更内容 + 影响面）；详情 SSOT 在 `architecture/<系统>.md` / 该仓 INFO-CARD（用户所述 CARD-INFO 即此，v0.4 architecture 是其绳上索引）。
3. **冲突（跨系统矛盾）**：B 发现 A 的矛盾 → B 分析 → 判断自己对时向 A 发起协商（在 A 的单上加 evidence 陈述，或 notice 指向 A）→ A 同意则修正关闭 → A 不同意才升级 PM。**复用现有原语（evidence + work item），不新增协商机制**（克制：新字段会变重）。
4. **PM 只做**：跨系统冲突仲裁、C2 对外契约破坏、生产权限授予、设计拍板。不是逐事审批人。
5. **accountable_human** = 最终问责归属，不是审批人。

**实现**：
- `model.TypeNotice` + validate 枚举 + web 词汇「通知」
- `workspace.Create`：notice 创建即 done（例外于 backlog 起步铁律）
- converge：notice 豁免 `done without evidence`（无执行无证据需求）；新增「依赖已全关但仍 blocked → 协商/决策僵持，建议 PM 仲裁」warning
- 修复根因 1：本铁律同时写入 AGENTS.md 注入面（不止档案）

**反事实复查**：①notice 破坏"新工作从 backlog 起步"？—— 该铁律防"新建即 done 跳过执行"；notice 无执行，例外正确，锁 `TestNoticeCreateDirectlyDone` 同时验证非 notice 仍 backlog。②协商需新原语？—— evidence 已支持在他人单上加陈述，A 回应即协商；新字段违反克制。③converge 僵持用时间阈值？—— 用「依赖全关仍 blocked」确定性逻辑矛盾，不引入 `time.Now()`（保持 converge 纯函数/可测）。④系统内部完全不建单是否丢可见性？—— 基石明定局部不上全局；代码 commit 可查（§21 残余风险已记录）。

**延后（记判据）**：notice 进 `context me`（判据：真实出现"通知未被目标系统读到"导致协作事故——当前靠 architecture/knowledge 索引 + work list 查询）；`consumers` 字段（判据：出现广播疲劳，需要点名受影响系统）；协商轮次结构化（判据：evidence 推断协商状态出现歧义）。

**锁**：`TestNoticeCreateDirectlyDone` / `TestConvergeNoticeNoEvidenceWarning` / `TestConvergeDependenciesResolvedStillBlockedWarns`。

## 30. doc bloat 三信号与 System 契约指针（2026-10-31，TASK-039，实栈 INFO-CARD 慢膨胀）

**起因**：实栈契约正本慢性堆积（data INFO-CARD 216KB / changelog 节 59%；mlake deploy 95KB）。pm 拍板「两层根治」：结构治理在系统仓（拆节+摘要化，TASK-036/038），巡检门禁在产品（本单 TASK-039，ousheng 系统首单——产品自身需求从此有归属系统，doc-lifecycle 步 2-4 类断点解除）。

**裁决**：

- **A. 三信号告警不拒绝**：① 契约面单文件 >30KB（`--bloat-bytes`）② changelog/history 节占比 >20%（`--bloat-changelog`）③ 环比激增 +20KB/7d（`--bloat-growth`/`--bloat-days`）。阈值 = CLI flags + 常量默认——**否决卡文"architecture 卡同款配置"**：v0.4 §4.1 architecture 纯 MD 零 schema，配置进卡即破坏「绳只索引文件名」；产品零配置文化，flags 即调参面。
- **B. 扫描范围追认**：卡文"与 orphan 一致（管辖域+镜像白名单+--dir）"沿用的是 §29 已否决的旧口径；落地 = §29 认领面 + 本单新增契约正本面。
- **C. System.contract_doc 契约指针（第四类认领）**：`system.contract_doc`（映射仓内相对路径）× `repos.yaml`（机器本地解析）→ `RoleContract`。投影模式第五实例：绳上投影 = architecture 卡，真本 = 映射仓正本。bloat 判、**陈旧不判**（契约版本机制另有 human_ack）；未映射/缺文件 = 该机不可见，静默跳过（best-effort 读面，与 DocUpdated 同语义）。声明暂走手改 systems.yaml（git 审计兜底）——CLI 写面判据见延后。
- **D. changelog 节口径**：标题含 changelog|history（卡文）**+ 变更记录|变更历史|更新历史**（实栈中文节名普遍，漏判即失效）；节 = 标题行至下一任意级标题（子节属历史）。
- **E. 环比取数**：`git rev-list --before` 定锚 + `git cat-file -s <rev>:<path>` 取 blob 字节（每仓一次锚定 + 每文档一次查询）。**bloat 输入只在 `doc check` 付账**（内容读取 + 环比 git），converge 路径只并入契约 refs（stat 级），不付此成本——巡检是主动查询，不是收尾必见。
- **F. 不误杀边界**（卡边界落地）：evidence 快照不判（900KB 验收报告合法）；未认领不判（先治无主）；健康文档零告警；0 = 关信号。

**反事实复查**：①契约合法增长被误杀？——只告警不拒绝，flags 可调可关。②映射仓不存在于本机（agent 机只映射自己系统）？——best-effort 跳过，PM 机/对应座位机可见即达巡检目的。③git 环比对新文档（无 7d 前版本）？——prev 缺项跳过 ③，①②仍判。④ContractRefs 混入 orphan/stale？——Claimed 恒真（契约认领即定义）、Updated 零值被 FindStale 跳过，两语义零扰动。

**延后（记判据）**：contract_doc CLI 写面（判据：第二个项目使用或手改出错实证）；bloat 进 converge 摘要（判据：PM 要求收尾必见膨胀）；RoleContract 陈旧判定（判据：契约过期致消费事故实证）。

**锁**：`TestChangelogRatio` / `TestContractRefs` / `TestBloatThreeSignals` / `TestDocCheckBloat`（真实 git 历史 + 映射仓联动）。

## 34. 巡航复盘与驾驶舱形态（2026-11-09，dev 双日巡航实栈复盘，P0-P4 全量落地）

**复盘数据**：dev 60h 交付 18/新增 28；handover 8 份四域在用；绳上"等 pm"类 evidence 仅 1 条（且是 pm 的自主性指令本身）——**绳上纪律良好，"频繁被扰"实感主体在会话层**（口头问不上绳、不可审计、不可批量）。

**五问题根因**（正推+反推）：中断/启动不了=驱动器单进程无监督+一击即停；视觉空等=sleep 盲轮询；空转=每轮浅推无收敛判据+同单停滞无人知；时间不确定=无可观测节拍；多窗口=PM 直操 N 会话（绳前形态）。

**核心裁决**：

- **A 模式坍缩**：巡航/普通二分坍缩为**在场度**（连续变量=决策响应预期）。`pm present/away` 一行事实（human 门才可声明；缺省=away 悲观默认）；agent 门行为单点分叉：present=问完等，away=挂起转下一活。全巡航可行——板成唯一界面，agent 窗口退为例外通道；需求入口恒 pm（域 agent 自提仅授权域 task/bug）。

### 57.1 问题重述（第一性）

一条裁决要改变行为，必须有一条从「裁决」到「运行时行为」的因果链。链上每一环要么是**机制**（代码在该处必然执行），要么是**读的人/模型照做**。只要有一环是后者，裁决的长期效力 = 读者每次都读、都记、都照做的概率乘积 → 趋零。实证四连：§51 绳牛（铁律躺在基石里四代无人对照）、§50-G presence（两轮各挂三天）、§50-A 单写源（8 天 11 次 merge）、「四剧本必跑」（红 8 天）。pm 的判断成立：**只要裁决是模型直接输出的文字，问题必然复发**；铁律清单本身也是文字——§52 的 `铁律对照:` 行是模型自证，§52 自己就预判了它「会沦为形式」。

失效机理归纳（七案对号）：F1 无绑定（纯文字）；F2 绑定腐烂（字符串锁当行为锁）；F3 信号被吞（读面错误 `_` 掉）；F4 入口漏盖（机制在，但仪式实际跑的入口没盖）；F5 量错尺（plan 文本 hash ≠ 板面 delta）；F6 人必做步（pm away / pull / 起驾驶舱 / 跑剧本）。

### 57.2 本体能解决吗——三案推演

**本体在本项目的定义**（§8.1）：词汇 / 类型 / 门 / 审计四层，无第五层推理机。

**方案甲：完整本体 + 推理机**（类 Incident/Ruling/Mechanism/Entry/Asset/Lock/Signal + 关系 + 约束 + 推理）。**否决**：
- 反事实 1（谁录入）：实例数据由模型会话录入——与写档案是同一个会话，漏录/错录概率相同；本体库与档案双源 → 必漂移 → 还要裁「谁是事实源」。本体只能是档案的结构化视图，否则违 E5「理由只在一处展开」。
- 反事实 2（推理机值多少）：约束只有六条完整性规则，百来行 Go 正则即可校验；推理机引入新依赖、新技能面、新腐败面，且「绳不变重」。
- 反事实 3（盖不住主要失效类）：F2/F4/F5 是语义判断（测试在测什么、仪式跑了哪些入口、尺子量的是不是该量的），任何本体都判不了。本体改变裁决的**表示**，不改变裁决的**执行**——「谁来把裁决翻译成机制」那一步原样存在。

**方案乙：薄治理词汇 + 校验器（裁决账本）**。**采纳**：档案每节（§56 起）带 `<!-- ruling: -->` 头，声明执行类型——`gate`（写路径门）/ `default`（悲观默认：忘记=安全）/ `meter`（量尺：失效自己显形）/ `lock`（行为锁）/ `hook`（流程钩：必经节点机械执行）/ `discipline`（纪律：会复发，只许作为带量尺、带复审日的临时态）。校验器 = `go test ./internal/govern`：

### 58.1 三类是一类：治理环对该故障不可观测

锁、尺、入口清单都是**代理**：锁代理行为，尺代理性质，清单代理「全部路径」。三者同病——故障发生时，治理环看的所有读数都没动：
- plugin 作用域缺陷：字符串锁绿，journal 无记录，板面 attach 无人看。
- plan 文本 cksum：plan 每轮都变，「有变化」恒真，退避读数永不触发。
- 晨检入口：`status`/`report` 输出看起来完全正常。

故障诊断理论的判据：故障 f **可检测** ⟺ 存在一个传感器，f 发生时其输出偏离常态。七案全是不可检测故障。这不是知识表示问题，是**传感器对故障不敏感**——再多的概念与公理不产生传感器，推理机在残差为零时什么也推不出。

### 58.2 根本解的形态：不是机制，是闭环性质

基石原则三/四已给出姿态：「慢采样反馈 + 人的监督，可替代精确的 plant 模型」「hook 硬保证 > skill 软纪律」。据此不建故障的完整模型（系统非平稳、故障是开放集），而是保证三条闭环性质：

- **P1 可检测**：每条裁决指名它的故障形态；其锁必须在那个故障上**红过**，其尺必须在**已知坏的现场样本**上读出过异常。没见过红的锁不算锁，没标定过的尺不算尺。
- **P2 覆盖由构造得出**：入口集合从代码派生（派发器即全集），不从文档清单抄。
- **P3 残差被采样**：现场信号进晨检，人慢采样。

人监督（C3 死区）不是缺陷而是设计：新故障形态在被观察到之前不可知。工具的职责不是消灭未知，而是**保证一看就看得出**（基石 C1 可观测性）。

### 58.4 发散过的其它路子与否决理由

- **LLM 评审锁的效力**：模型输出——正是「模型直接输出的裁决会复发」同一病；只可作顾问（曝光），不可作机制。

- **运行时遥测 / 常驻自检进程**：违「禁 daemon」。门的拒绝事件目前只有 stderr / journal，跨机不可聚合——记为缺口，判据：第一次因「不知道昨夜哪些门拦了谁」而误判 → 做门拒绝日志本地落盘 + doctor 汇总。
- **属性测试 / 模糊测试生成新剧本**：违 E4（禁预防性剧本）。
- **双尺交叉**（内外两把独立尺，不一致即报警）：成本翻倍，只给高风险裁决作惯例（token：驱动器自报 vs provider 账单）。

### 58.5 反事实

- 回放会腐烂吗？锚点写死在测试里——资产一改，回放要么仍成立，要么响亮失效；没有静默绿的路径。
- 回放是不是「为已锁机制再造验证层」（A2）？它验证的对象是**锁本身**，不是机制；机制的行为锁只有一份，回放只是让那把锁看一眼缺陷。
- 「根本解决」了吗？对**已知故障形态**：是——可检测性可机械立住。对**未知形态**：不可能，也不该假装——那正是人监督的位置。控制论姿态不变：慢采样 + 人监督 + 不替牛。
- **账本在真实失误上的首次触发（同日）**：把驱动器行为锁重构成共用函数时，脚本按标记切片误删了同区间的另外三把锁（`TestWebCruiseHidesStateLine` / `TestOversizedCardAllowsNonGrowthWrites` / `TestWebTokenFromEnv`）——编译照过、剩余测试照绿；是 `TestRulingLedger` 的 V2（锁名必须是真实测试函数）当场报红。这比合成用例更直接地回答了 §57 反事实 6（会不会沦为形式）：至少「锁被悄悄删掉而账本还写着它」这一类，机械可查。
