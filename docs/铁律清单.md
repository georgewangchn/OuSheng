# OuSheng 铁律清单（一切产品改动的前置门）

> **用法**：任何产品改动（fix / feat / refactor / 裁决 / 文档）动手前过一遍本清单，
> commit message 带 `铁律对照:` 行（写「无涉」或列出相关条目号 + 为何不违）。
> 缺行 = 不合规格的改动，复盘时一眼可见。清单是单点权威，AGENTS.md 是其注入摘要。
> 依据：档案 §52（2026-11-16 pm 裁决——§51 绳牛违例四代无人对照的实证）。
> F 类新增（2026-11-21）：入口自检四律——§54/§55 三轮实锤 + review 修订 + 漏洞审计
> 收敛成律（目标/痛点/落地面前置节，档案 §55 全记录）。

## F. 自检类（入口验证运行时假设——2026-11-21 三轮实锤收敛成律）

> **目标**：绳的每个入口（plan/ignite/sync/web 刷新）在使用前验证「运行时假设仍然
> 成立」——把事故发现从「事后考古」变成「入口自动」，全部零模型 token（纯 git/本地
> 机械操作，不碰牛的语义域）。
> **痛点实证**：拓扑分裂整夜盲跑（各源 sync「ok」但互缺——**「ok」不含新鲜度**，T-226
> 盲区④）；人工拓扑约定必复发（11-16 修过 11-20 又裂）；配置漂移三连（截止过期差点
> 点火秒停 / 轮顶 200 历史漂移 / CODE 槽退化 flash）；连败 exit 0 躺平死；网络半开
> 把自检链自己 hang 成死锁源。**已落地面**：ignite 五道门 / plan 三联门 / sync 水位
> 摘要 / doctor 拓扑+URL 交叉 / web 轻检 chip / git 超时层 / 连败 exit 1 自愈。

| # | 铁律 | 自查问句 | 破坏实例 |
|---|---|---|---|
| F1 | **入口自检**：高频入口先验运行时假设（分支=main / 多 remote 无缺新 / 截止未过期 / 路由未退化），「ok」必须含新鲜度语义 | 这个入口信了什么假设？假设破了谁看见？ | §54/§55：席位看旧板整夜盲跑 53 提交 |
| F2 | **hard/soft 分离**：确定性风险（remote 有本地缺的新）拒；不确定态（网络不可达/仅未推）降级警告——不狼来了也不吞真信号 | 拒的是「确定会坏」还是「可能不稳」？常态场景会不会误报？ | review 🔴1：归档镜像常态落后曾致 chip 常亮 |
