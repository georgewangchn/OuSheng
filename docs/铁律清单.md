# OuSheng 铁律清单（一切产品改动的前置门）

> **用法**：任何产品改动（fix / feat / refactor / 裁决 / 文档）动手前过一遍本清单，
> commit message 带 `铁律对照:` 行（写「无涉」或列出相关条目号 + 为何不违）。
> 缺行 = 不合规格的改动，复盘时一眼可见。清单是单点权威，AGENTS.md 是其注入摘要。
> 依据：档案 §52（2026-11-16 pm 裁决——§51 绳牛违例四代无人对照的实证）。

## A. 绳牛类（产品定位——破坏代价最大）

| # | 铁律 | 自查问句 | 破坏实例 |

| A1 | 绳不替牛干活：最小接触面，只给方向，不做牛的决策（排活/排序/步幅/语义判断） | 这个改动是在替模型/人**决策**，还是在提供**事实与门**？ | §51：plan 清单+优先序+一次一轮注入 prompt，四夜 111 轮干不过一句话 session |
| A2 | 不为已锁机制再造脚本/验证层 | 已有 Go 锁/dogfood 覆盖吗？ | §17：冗余验证层会腐烂 |

| A4 | 零 schema/零白名单：不引入 JSON Schema/白名单/镜像清单类项目习惯 | 新增了"要维护的清单"吗？ | §29 裁决 B |
