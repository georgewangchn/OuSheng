# WTH 完整设计方案（With Two Human）

> 本文是在 [方案基石](../../多人AI协作机制_方案基石.md) 之上的**完整产品设计**。基石定义了设计原则与逻辑边界；本文把这些原则落成具体的数据模型、接口、协议与落地路径。
>
> **方法论铁律**：设计思考必须完整且前瞻，面向最终可交付产品；实现落地才分阶段（先易后难）。本文描述的是**最终形态**，不是 MVP。
>
> **验证铁律**：每一个设计元件都必须通过基石的判断四关，并复核第一性原理——
> 1. 服务于 C（跨边界必需）还是 I（局部实现）？
> 2. 去掉它系统还能协作吗？
> 3. 它是"绳"还是"替牛使劲"？
> 4. 它破坏 C1 / C2 / C3 中任何一条吗？
>
> 过关即正确，不过即删。本文对每个前瞻元件显式记录了这一推演，其中反事实推演砍掉了 ASR 组件、并强制"渐进式上下文披露"离开看板。

---

## 0. 定位复述

WTH 是套在"AI Coding 这头黄牛"鼻子上的**牵引绳**：用最小接触点给方向，绝不替牛使劲。机制与具体 AI Coding 工具（Claude Code / opencode / Codex / Pi / 人）解耦。

第一性事实：**对外协作所需信息 C ≪ 内部完整状态 I**。任何让全局承载 I 的设计从第一性原理即错误。

## 1. 最终产品形态（工具无关）

一个 core lib，多个薄适配前端，任何 AI Coding 工具即插即用：

```
        ┌──────────────── core lib (Go) ────────────────┐
        │ 存储 · CAS · schema 校验 · 状态机 ·             │
        │ 全局归约 · DAG 检测 · 投影闸门 · 签名验证       │
        └───┬────────┬──────────┬───────────┬────────────┘
        board CLI  MCP server  Claude hook   opencode
       (通用/脚本)  (opencode等) 适配器        plugin 适配器
                                └── 全是薄壳，零重复业务逻辑 ──┘

        store = git 仓（cards/<id>.yaml，version / 历史 / 签名白送）
```

**技术选型与理由：**

| 物件 | 形态 | 理由 |
|---|---|---|
| core lib | 单一 Go 包，承载全部逻辑 | 单一真相源，杜绝多前端逻辑漂移 |
| `board` CLI | 单静态二进制，core 的规范入口 | 任何工具/脚本可 shell 调用；零运行时依赖；subprocess 启动快；裸兜底 |
| MCP server | Go 二进制，import 同 core | opencode 等原生调用；零重复逻辑，即"骑 CLI" |
| Claude hook / opencode plugin 适配器 | 各工具原生扩展，内部打同一 core | 按工具能力挂最硬的采样保证 |
| store | git 仓，一卡一文件 | version / 历史 / Owner 签名白送，无需自建 |

**语言选型**：Go。单二进制分发、启动快（跨工具高频 shell 调用）、git / yaml / jsonschema 生态齐全。TypeScript 写 MCP 更快，但 Node 启动慢、需运行时依赖，作为裸兜底 CLI 不合适——故弃。

**反事实自查**：去掉 CLI？opencode 走 MCP 够用，但绑定 MCP 环境，违背工具无关——保留。去掉 core lib 各前端各自实现？两份逻辑必然漂移——保留。三件都承重。

## 2. 数据模型：卡片 Schema ＝ 接口标准量纲

这是工具**唯一必须做到极致**的东西之一（另一件是把看板呈现清楚）。如同控温前必须先定义"温度"，动工前必须先钉死这套量纲。

一卡一 YAML 文件。字段严格锁死，多一个顶层 key 直接拒（投影硬闸门）：

```yaml
id: user-auth-api             # 稳定 slug，全局唯一
owner: backend                # 节点身份（git author 映射）
task: "提供用户登录鉴权接口"     # 一句话意图 = 人给的方向（参考信号 r 的语义）
status: proposed              # proposed | agreed | live | verified | deprecated
version: 3                    # int，CAS 乐观锁，每次变更 +1
depends_on: [db-schema]       # 依赖的卡 id 列表，强制构成 DAG
contract:
  kind: http                  # http | cli | lib | event
  breaking: false             # 本版本是否破坏下游？true 触发 C2 限速器，需人批
  interface:                  # kind 相关的结构化接口定义
    - method: POST
      path: /login
      request:  { body: { email: string, password: string } }
      response: { "200": { token: string, expires_in: int },
                  "401": { error: string } }
      behavior: "有效凭证返回 token；无效返回 401"   # 行为语义——探针据此测
evidence:                     # status=verified 时必填（7.4 行为级传感）
  probe: "test/auth_integration: POST /login 200 + token 可用"
  passed_at_commit: abc123
  by: frontend                # 消费方探针，非生产方自证
human_ack:                    # 仅当 contract.breaking=true 时必填（C2 限速器）
  approver: alice             # 批准 breaking 变更的人
  at_version: 3
```

> **签名不进卡内**：Owner 身份即声明的 `owner` 角色；参考信号完整性由 **git commit 签名**（MVP=git author，前瞻=GPG/sigstore）在 `read_board` 时验证。把签名写进被签名的卡内容里是循环、且是冗余的 I——按原则四删除该字段。

**关键设计点（逐个对应基石防线）：**

- **`behavior` 字段 = C1 生死线的落点**。契约不能只有形状，必须携带行为语义，否则"形状对、语义错"的实现能骗过下游（基石 7.4）。消费方探针依据 `behavior` 测真实接口。
- **`breaking` 字段 = C2 限速器**。加法/非破坏性变更 `breaking:false`，由 agent 自主吸收（C3 死区）；`breaking:true` 必须携 `human_ack`，否则写入被挂为 pending-human。契约变化被强制慢于内环收敛。
- **`evidence` = live→verified 的准入**。无探针证据不许写 verified，硬闸门校验字段存在，防假 verified 污染下游。注意闸门只能校验 evidence **存在**，不能校验探针真的跑过（那在 plant 内）——这条纪律的另一半靠采样点的行为探针（§5.3）。
- **`human_ack` = C2 限速的落点**。`breaking:true` 而缺 `human_ack` 的写入被 `write_board` 挂为 pending-human，不进板。
- **`depends_on` = DAG 约束的数据基础**。见 §5。
- **投影硬闸门**：未知顶层 key 拒、卡超尺寸（默认 8KB）拒。**结构化 contract 字段本身允许**（它就是契约）；禁的是往任意字段里塞围栏源码块 / stack trace / memory / 调试日志。schema 校验会被执行，skill 会被忽略——故硬闸门必须落在 core lib，而非协议文档。

**两类卡共用此 schema：**
- **reference 卡**（`proposed`）：生产方或消费方任一方均可发起，声明"我承诺提供"或"我需要"的契约形状。解决冷启动与消费方驱动。
- **verified 产出**（带 `evidence`）：已被行为探针确认与现实一致的实际产出。

消费方发需求卡不违背"局部复杂、全局简单"——它写出的仍只是契约形状，而非自身实现、Memory 或推理。

## 3. Actuator API（最终形态：core lib 为真相，CLI / MCP / 适配器全转发）

三个函数，对应控制论的边界采样。actuator 是采样-保持的"线"，本身不持有业务状态。

### `read_board(scope) → cards[]`
纯读，无副作用。`scope` 过滤 `{ id | owner | status | depends_on | kind }`。返回匹配卡的投影，即采样参考 r（本任务契约 + 依赖方契约变更＝阶跃扰动）。

### `write_board(card, expected_version) → ok{new_version} | conflict | rejected`
发布投影 y 或 reference 提议。四道内建闸门：

1. **CAS（版本乐观锁）**：`expected_version ≠ 当前值` → `conflict`。协议规定：重读 → 调和 → 重试；不可调和则上抛人。CAS 的"读-比-写"必须原子（否则并发写产生竞态）——落地借 git 提交的原子性：写文件后带前置 ref 提交，ref 已移动则提交失败、退回 conflict（见 §8 阶段1）。
2. **Schema 校验（量纲）**：不合规 / 未知 key / 超尺寸 / 含 code·stack·memory → `rejected`。**运行时最关键的一道门。**
3. **状态机强制**：仅允许合法迁移（见 §5）；`verified` 必须携 `evidence`；`deprecated` 级联标记下游需迁移。
4. **breaking 限速**：`breaking:true` 必须携 `human_ack`，否则挂 pending-human（C2）。

写入成功 = 一次 git commit = version + 历史 + Owner 签名一次性落地。

### `converge(scope) → { status, blockers[], cycles[] }`
看板上的纯归约函数，任意节点或人都能在本地对看板计算得出，无 daemon、无中心大脑。

**`broken` / `stuck` 不是存储的 status（枚举保持 5 态），而是 converge 在 `(status, 时间戳, 依赖态, evidence 新鲜度)` 上算出的派生谓词**：`stuck` = 卡在同一 `(status, version)` 停滞超过 N 周期；`broken` = verified 卡的依赖被 deprecated、或其 `evidence.passed_at_commit` 已陈旧于当前实现。

- **GLOBAL CONVERGED** ⟺ 所有契约 `status=verified` ∧ 均带 `evidence`（board 不跑探针，探针在消费方 plant 内跑）∧ 无 `proposed` 悬挂 ∧ 无派生 `broken` ∧ DAG 全部满足。
- **GLOBAL STUCK** ⟺ 存在派生 `broken`/`stuck` 持续 N 周期 ∨ 死锁（A 等 B ∧ B 等 A）∨ 依赖成环。
- 否则 **IN_PROGRESS**。

三个函数都是 core lib 函数；CLI 暴露为 `board read | write | converge`；MCP 暴露为同名工具；hook / plugin 适配器内部调同一 core。

## 4. 采样纪律与保证矩阵（覆盖所有工具）

一次 loop 迭代 = 一个控制周期，两个采样点：

```
loop 开始 ── read_board ──► 采样参考 r（我的契约 + 依赖方契约变更＝扰动）
     │
     ├─ agent + human 编码 + 跑自己的测试 ──► plant 内部闭环，把本地误差 e→0
     │
loop 结束 ── write_board ──► 发布投影 y（Contract / Status），成为他人的 r / 扰动
```

本地环在 plant 内部已自闭合（agent 自己的测试＝传感器，AI Coding 工具自带的写→测→改收敛环＝控制器）。边界采样只负责环与环之间的耦合，不介入环内。这是采样控制（sampled-data control），也是最小接触点的牵引绳。

**read 必须发生，否则本地环开环、在陈旧或空的参考上瞎跑。** 按工具原生能力取最硬档，全部打同一 core：

| 工具 | 保证硬度 | 机制 |
|---|---|---|
| Claude Code | 硬 | `SessionStart` hook 强制注入 read；`Stop` hook 强制 write |
| opencode | 半硬 | plugin 的 session 开始/结束事件触发 read / write |
| pi / codex / 人 / 无 hook 工具 | 软 | skill 纪律 + 每周期把看板投影注入上下文文件 |

- **discipline = skill `board-protocol`**：采样律（何时读写）+ 投影律（只吐 C，绝不吐 I）+ 冲突处理。跨工具的可移植形态是一份协议 markdown（等价 AGENTS.md 类规则文档）。
- **两道投影闸门（纵深防御，运行时守住 C ≪ I）**：
  - 软：skill 指示"只投影"。
  - 硬：`write_board` 对 schema 做校验，不合规/超尺寸直接拒。
  - skill 会被偶尔忽略，schema 校验不会。硬闸门必须落在 actuator 里。

**风险与验证点**：opencode plugin 事件是否覆盖 session 开始/结束、能否在其中执行 I/O，需在落地阶段 3 实测确认；MVP 不依赖它（先软后硬）。

## 5. 全局收敛、生命周期与 DAG（补齐非稳态）

§1–§4 定义了稳态控制动力学。完备性要求还需回答：参考信号如何诞生、协作整体何时收敛或卡死、依赖成环时如何保稳。三者的解都不引入新机械。

### 5.1 参考信号生命周期（genesis）
落在卡的 `status` 一个字段的状态机上：

```
proposed ──► agreed ──► live ──► verified ──► deprecated
   ▲            │          │
   │(任一方发起) │(仲裁通过) │(探针未过则回退 live)
   └────────────┘
```

- **proposed**：任一方（生产或消费）创建，解决冷启动与消费方驱动。
- **agreed**：契约 Owner 与受影响方达成一致。**仲裁权归契约 Owner，消费方只能提议；** 分歧上抛更高层人类。
- **live**：Owner 开始实现，契约成为下游可依赖的参考。
- **verified**：消费方行为级集成探针通过（见 5.3），契约被确认与现实一致。
- **deprecated**：契约退场，依赖它的卡被标记需迁移。

诞生、协商、派发、退场全部在此一字段闭合，零新机械。

### 5.2 全局活性判据
即 `converge()` 的归约（§3）。人看一眼看板即知全局是否收敛、卡在哪张卡。全局可观测性由此闭合。

### 5.3 DAG 约束与行为级传感
- **DAG**：`depends_on` 强制无环。write 或 converge 时判环，成环判 `GLOBAL STUCK`，交由人打断（拆分契约或引入更慢的共享仲裁点）。这是**保守安全近似**，非"环必失稳"。
- **行为级传感（硬化 C1，7.4）**：`live→verified` 的准入必须由消费方的**行为级**集成探针把关（测真实交互是否产出所需结果），不能只做 schema 形状校验。

## 6. 前瞻层（每件过四关，反事实真砍了元件）

### F1 渐进式上下文披露（§5 降级路径）——过关，但反事实强制"离板"
- 服务 C：默认 Level 0（Contract）即纯 C。去掉还能协作？强命题下能（L0 足够）→ 是降级层，纳入最终设计做鲁棒性。
- **反事实咬出矛盾**：§5 允许 `Level 4 = 原始上下文`跨界，直接撞原则一（I 永不跨界）与 §6.5（write 只吐 C）。
- **裁决**：看板**永远只存 Level 0（Contract）**；`Level 1 接口细节 → L2 架构 → L3 实现 → L4 原始上下文`走 **owner 节点的按需拉取通道**，即用即弃，**绝不落板**。通道**只做原始透传**（owner 暴露已有产物，请求方 agent 自己读），一旦加摘要/合并即成语义合并器＝替牛使劲＝删。
- 这保住了看板的 C ≪ I，同时实现最小权限式的 Least Context Principle。默认 L0，仅在证据不足时逐级下探。

### F2 签名信任——过关，最终形态 = git commit 签名
- 服务 C（参考信号完整性，§3 要求每张卡由 Owner 签名）。去掉？单组织可信下能协作 → 是联邦/多方场景的前瞻。
- 最终形态：git commit 签名（GPG / sigstore）= Owner 身份，`read_board` 时验签。绳，不碰牛的活。

### F3 ASR 作为组件——反事实砍掉
- 去掉 ASR，5 人团队照常协作（基石明说非核心）。且收敛环 = 控制器 C，AI Coding 工具自带 → 建 ASR = 重造控制器 = 替牛使劲。
- 其残余价值两块已被吸收：行为级 verified 纪律**已在 `write_board` 的 evidence 闸门里**；"守规矩节点"降级为**交付物中的一个参考示例（文档级）**，非产品组件。
- **结论：最终产品不含 ASR 组件。**

### F4 多工具联邦——不是新元件，git remote 白送
- 跨节点传 r = git push / pull = 采样总线本身。任何 relay / P2P discovery / NAT 基石已禁。
- 联邦 = 共享 git 仓的 push-pull，零新机械。

## 7. 系统不保证什么（scope 边界，第一性直接推出）

控制论硬边界：**你可以完美地跟踪一个错误的参考信号。**

- **保证**：一致性 + 向参考收敛。各局部环收敛到 `agreed` 契约；`converge` 判定全局一致/卡死；契约与现实的偏差被消费方行为探针检出并驱动修复。
- **不保证**：意图正确。若被 `agreed` 的契约本身是坏设计，系统会把所有人一致、忠实地收敛到这个坏契约。方向对错是人/产品的判断，位于控制环之外——正是牵引绳定位：人握绳定方向，工具只确保牛忠实前行。
- `unverified` / 探测不到的依赖会**永久阻挡 GLOBAL CONVERGED**。这是故意的诚实信号（你确实无法确认它能跑），不是死锁 bug。
- §5.3 的"依赖成环即判 STUCK"是**保守安全近似**，非"环路理论上必然失稳"。

## 8. 实现落地分阶段（设计已完整；此处排先易后难，终点 = 上述完整设计，非缩水品）

> 落地顺序的首个选择：**opencode 优先 / MCP 骑 CLI / 采样先软后硬 / 首验证场景为前后端双 agent 单仓。** 这些只影响阶段排序，不裁剪 §1–§7 的设计。

| 阶段 | 目标 | 产出（可跑增量） |
|---|---|---|
| **0 纸面闸门** | 确认 C1 成立 | 目标场景接口可真实探测的纸面确认；**钉死 §2 的 schema 量纲**（唯一必须最先定的东西） |
| **1 core lib + CLI** | 裸兜底可用 | store / read / write / converge + CAS + schema 校验 + 状态机 + DAG + 投影闸门；TDD 全覆盖 |
| **2 MCP + opencode 接入** | 实证三防线 | MCP server；软纪律 skill 注入投影；实跑前后端双 agent 单仓，验证 C1（探针检出漂移）、C2（version 锁 + breaking 人批）、C3（加法自吸收） |
| **3 半硬采样** | 补齐保证矩阵 | opencode plugin 事件触发采样；Claude Code hook 适配器 |
| **4 前瞻层** | 鲁棒 + 联邦 | F1 按需拉取通道、F2 验签、`converge --watch` 全局看板、deprecation 迁移流 |
| **5 交付** | 最终产品 | 分发二进制 + 各工具适配包 + 协议 markdown + 参考节点示例(F3) + 文档；工具无关性证明（≥2 工具同板协作） |

先易后难 = CLI → MCP → plugin/hook → 前瞻 → 交付。每阶段可独立运行，末端收敛到 §1–§7 的完整设计。

## 附：判断任何新提议是否纳入的唯一流程
